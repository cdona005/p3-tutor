# Sources for lesson 0002 (O2: the goal of an agent harness)

All pages opened 2026-11-17.

## Primary

### Agent SDK docs: How the agent loop works
- URL: https://code.claude.com/docs/en/agent-sdk/agent-loop
- Who: Anthropic, official Claude Code / Agent SDK documentation.
- Why primary: the one page that covers all four duties named in the objective with concrete defaults. It does not itself define the word "harness"; pair it with the Claude Code page below for the definition.
- Supports:
  - Loop: the SDK "runs the same execution loop that powers Claude Code"; one turn = Claude output, SDK runs requested tools, results feed back; repeats until a response has no tool calls, then a `ResultMessage` carries text, usage, cost, session ID.
  - Tool execution: "The SDK runs each requested tool and collects the results." Read-only tools may run concurrently; Edit/Write/Bash run sequentially. A denied tool returns a rejection message as the tool result.
  - Context: the window accumulates system prompt, tool definitions, history, tool outputs; when near the limit the SDK auto-compacts (summarizes older history, emits `compact_boundary`); compaction can lose early instructions, so persistent rules go in CLAUDE.md; subagents keep their transcript out of the main context.
  - Limits: `max_turns` and `max_budget_usd` both default to no limit; hitting them gives `error_max_turns` / `error_max_budget_usd` with no `result` field; budget can overshoot by one response; budget covers subagents.
  - Permissions: `allowed_tools`, `disallowed_tools`, `permission_mode` (default, acceptEdits, plan, dontAsk, auto, bypassPermissions); hooks (`PreToolUse` etc.) can block a call before it runs, and run in the app process so they use no context.

## Others

### Claude Code docs: How Claude Code works
- URL: https://code.claude.com/docs/en/how-claude-code-works
- Who: Anthropic, official documentation.
- Supports:
  - The definition: the loop "is powered by two components: models that reason and tools that act. Claude Code is the layer around the model that provides the tools and manages the context the model sees. This surrounding layer is what the term agentic harness refers to."
  - Without tools the model "can only respond with text"; tool results feed the next decision.
  - Context: window holds history, file contents, outputs, CLAUDE.md, skills; auto-compaction; early instructions can be lost; sessions are independent (fresh context each).
  - Safety: checkpoints for file edits (not remote actions) and permission modes (Auto, Manual, Accept edits, Plan).

### Anthropic Engineering: Effective harnesses for long-running agents (Justin Young, 2025-11-26)
- URL: https://anthropic.com/engineering/effective-harnesses-for-long-running-agents
- Who: Anthropic Engineering.
- Supports (why an agent needs one): agents work in discrete sessions and each new session starts with no memory; context windows are limited and complex projects do not fit in one; the post calls the Claude Agent SDK "a general-purpose agent harness" that runs the model in a loop across context windows with context management including compaction; compaction alone is not enough, so a harness needs artifacts (progress file, git history) to carry state between sessions.
- Note: the post gives no formal definition of "harness"; the long-running-project design (initializer plus coding agent) is beyond a 15-minute O2 lesson.

### Anthropic Engineering: Building effective agents (Erik S. and Barry Zhang, 2024-12-19)
- URL: https://www.anthropic.com/engineering/building-effective-agents
- Who: Anthropic Engineering. (Opened directly this session; this resolves the gap listed in RESOURCES.md.)
- Supports (why limits and guardrails): agents are "typically just LLMs using tools based on environmental feedback in a loop"; stopping conditions such as a maximum number of iterations keep control; autonomy brings higher cost and "the potential for compounding errors", so test in sandboxes with guardrails.

### Claude API docs: Tool use with Claude
- URL: https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview
- Who: Anthropic, official API documentation.
- Supports (why a model needs something around it): the model only returns a structured call; for client tools it answers `stop_reason: "tool_use"` with `tool_use` blocks and "your code runs the operation and sends back a `tool_result`". That code is the harness's job; the model itself executes nothing (server tools like web_search are the exception, run by Anthropic).

### Arize: What is an agent harness? (Aparna Dhinakaran, April 2026)
- URL: https://arize.com/blog/what-is-an-agent-harness/
- Who: Arize AI, an observability vendor, so a secondary vendor source; use only as a cross-check, not as the lesson's authority.
- Supports: harness is "the runtime layer that wraps a language-model agent so it can act reliably in production"; a model alone is a one-shot text generator; components: iteration-capped loop, tool registry with permission check before execution, context assembly and compaction, permission modes, output truncation limits, subagents, session persistence.
