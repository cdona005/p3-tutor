## The win

By the end the learner can look at a failing or misbehaving agent run and say which of the harness's four duties (loop, tool execution, context, limits and permissions) is responsible, and explain why a bare model cannot do any of them.

**Mission tie:** the mission asks for "how their loops run, stop and fail" and for predicting how a change to the tutor's config changes its behavior. The tutor is a harness config (skills, `allowed` tools, caps), so knowing what the harness owns tells the learner which knob changes what, before spending bench usage.

## Ideas the lesson teaches

Taught in full:

1. Why an agent needs a harness: the model alone only returns text or a structured tool call (`stop_reason: "tool_use"`); nothing runs it, nothing remembers across calls, nothing stops it. Definition: the harness is the layer around the model that provides the tools and manages the context (How Claude Code works). Placed first, as the problem.
2. Duty: runs the loop. Turn = model output, harness runs tools, results go back; repeat until a response has no tool calls. Builds directly on lesson 0001, so a recall, not a re-teach.
3. Duty: executes tool calls. The model emits `tool_use`; harness code runs it and returns `tool_result`. Read-only tools may run concurrently, Edit/Write/Bash run sequentially.
4. Duty: manages context. The window accumulates system prompt, tool definitions, history, tool outputs. Near the limit the harness auto-compacts (summarizes older history). What to do about the trade-off: compaction can drop early instructions, so put persistent rules in CLAUDE.md; subagents keep their transcript out of the main context.
5. Duty: enforces limits. `max_turns` and `max_budget_usd` both default to no limit. Hitting one gives `error_max_turns` / `error_max_budget_usd` with no `result` field; budget can overshoot by one response. What to do: set a cap deliberately, and check the subtype before reading `result` (ties back to O1).
6. Duty: enforces permissions. `allowed_tools`, `disallowed_tools`, `permission_mode`, hooks that can block a call before it runs. A denied tool does not crash the run: the model receives a rejection as the tool result and the loop goes on. Tie to the learner's own tutor: in a bench run any tool not in `permissions.allow` (plus Glob and Grep) is denied.

Left out:

- Refusal, `pause_turn`, `model_context_window_exceeded` handling, and the rest of the stop-reason catalogue: already flagged for a later O1 follow-up, and this lesson is about the harness, not stop reasons.
- Hook types in depth, `permission_mode` values one by one (name the idea and mention that modes exist; list at most two examples), checkpoints, sessions and resume: side detail for 15 minutes.
- Long-running-agent design (initializer agent, progress file, git as memory) from the Effective harnesses post: beyond O2; offer it as a "Go further" link only.
- Comparing harnesses across frameworks (AI SDK etc.): out of scope in MISSION.md.

## Warm-up (about 200 words with the opening)

1. A loop ends after a reply with text only and no tool call. Is that the same as the task being done? (Answer: no; it is the loop's exit, and `result` exists only on success. This also recalls M1.)
2. A run was cut off with `max_turns=3` after three tool-calling turns. What does the result show? (Answer: subtype `error_max_turns`, no `result` text.)

Both feed straight into the limits section.

## Misconceptions

| To name | Section | Why it is tempting |
|---|---|---|
| The model runs its own tools (proposed M3) | 2 and 3 | Chat UIs show "Claude ran the tests" as one event, so the harness is invisible. The API reality: the model emits `tool_use`, your code runs it |
| Limits are on by default, so a runaway loop stops itself (proposed M4) | 5 | Hosted products have caps, so one assumes the SDK does too. The loop page says both `max_turns` and `max_budget_usd` default to no limit |
| Any stop returns an answer in `result` (existing M2, revisited) | 5 | Carried over from O1: the text on the last message looks like an answer. `error_max_turns` and `error_max_budget_usd` have no `result` field |
| Compaction keeps everything, just shorter, so early instructions are safe (proposed M5) | 4 | "Summarize" sounds lossless. The docs warn early instructions can be lost, so rules go in CLAUDE.md |
| A denied tool call ends the run (proposed M6) | 6 | Exceptions are how CS programs usually signal denial. Here a rejection is returned to the model as the tool result, and the loop continues |
