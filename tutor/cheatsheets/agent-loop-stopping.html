How an agent loop stops

Covers: Lesson 1, How an agent decides it is done

The model

The harness runs a while loop: go again while the latest reply asks for a tool; the only finished state is a reply with no tool call, read from stop_reason, never from the words.

Every other ending (truncated reply, turn or budget cap) is a stop, not a success, so classify it by its signal before using the output.

while True:
    reply = call_model(messages, tools)     # 1 turn
    if reply.stop_reason == "tool_use":     # run tool, append result, loop
        ...
    elif reply.stop_reason == "end_turn":   # only natural finish
        break
    else:                                   # max_tokens / context full:
        ...                                 # truncated, NOT an answer
# caps (max_turns, max_budget_usd) sit in the harness, around the loop
# bug: the lesson's basic loop has a bare `else: break` here

Reading a run: check the subtype, then read result only on success.

Know cold

  1. The harness decides, from stop_reason: tool_use = run tool, append, call again; end_turn = exit. → s1
  2. Completion is structural (no tool call), never wording like "done". → s2
  3. max_tokens / model_context_window_exceeded = truncated: don't return it, don't run a tool call in it. → practice
  4. max_turns needed = tool-call turns + 1 for the final text-only reply. → worked example
  5. Subtype first: only success carries result; a cap says nothing about whether the task got done. → s3

Counting and defaults

  • Turn = one model call plus the tool runs it triggers.
  • max_turns needed = tool-call turns + 1.
  • max_turns and max_budget_usd: both unlimited by default in the Agent SDK.
  • CS frame: stop_reason is a return code; the reply's words are a log line.

Self-test

Cover the sheet first. Hardest first: 3, 5, 4, 6, 2.

  1. recallWho decides whether to call the model again, and from which field?
    Answer

    The harness, from stop_reason on the latest reply: tool_use = go again, end_turn = exit.

  2. compareHarness A exits when the text contains "finished". Harness B returns the reply whenever stop_reason != "tool_use". Name one way each goes wrong.
    Answer

    A: exits early on "finished reading, now editing" with a pending call, or spins on when the word never appears. B: returns a max_tokens or context-exceeded reply, which is truncated, as the answer.

  3. applyA reply stops with max_tokens and its last block is a write_file tool call. Run it? Why?
    Answer

    No. The reply is truncated and the call may be incomplete. Raise max_tokens and retry, or ask the model to continue.

  4. applymax_turns is 5. The model makes 4 tool-call turns, then a text-only reply. Subtype, and is there a result?
    Answer

    success, with a result: 4 + 1 = 5 fits exactly.

  5. applyStop reasons would arrive tool_use, tool_use, end_turn, and max_turns is 2. How does the run end?
    Answer

    error_max_turns, no result: the cap is reached after the two tool-call turns, before the final reply.

  6. spot the bugA dashboard counts a run as succeeded whenever its subtype is not error_during_execution. What is wrong?
    Answer

    error_max_turns and error_max_budget_usd are not successes either. Only success is.

  7. compareSort into reply-level or run-level: max_tokens, max_budget_usd, model_context_window_exceeded, max_turns.
    Answer

    Reply-level (from the API): max_tokens, model_context_window_exceeded. Run-level (harness caps): max_budget_usd, max_turns.

  8. whyA run ends error_max_turns right after its last tool call succeeded. Why can't you treat it as finished?
    Answer

    A cap stops a run whether or not the task is done. No final response was produced and there is no result; only success means success.

  9. applyYou set neither max_turns nor max_budget_usd, and the model keeps requesting tools. What ends the run?
    Answer

    No cap does: both are unlimited by default. Only the model's own choice, a reply with no tool call, ends the loop.

  10. whyIn CS terms, why is stop_reason a better exit test than the reply's words?
    Answer

    It is a structured value, like a return code; the words are like a log message. Branch control flow on structure.
