The loop and its one exit 2 min

Problem: a model only produces text, or a request to call a tool. Who decides whether to go around again?

The harness (the program around the model) does, by reading one field on each reply. Each reply carries a stop_reason, which says why the model stopped generating. Two values drive the loop (Anthropic: handling stop reasons):

  • tool_use: Claude is calling a tool. Run it, return the result, call the model again.
  • end_turn: Claude completed its response naturally. Use the response.

In CS terms it is a while loop whose condition is "the last reply asked for a tool". The Agent SDK states the same rule: turns continue until Claude produces output with no tool calls, and then the loop ends and the final result is delivered (Agent SDK: how the agent loop works).

# Basic tool loop (shape taken from the Messages API docs)
while True:
    reply = call_model(messages, tools)           # one model call = one turn
    if reply.stop_reason == "tool_use":           # model asked for a tool
        results = run_tools(reply.content)        # harness executes it
        messages.append(assistant(reply.content)) # keep the history
        messages.append(user(results))            # feed results back
    else:                                         # no tool call: exit
        break

Why not check for "done"? 2 min

Problem: a model often writes "Done." or "All finished." in plain text. Why not exit when you see that?

A common mix-up

"The agent is done when it says it is done." It is tempting because it matches how people talk. But a reply can say "Done reading the file, now editing it" and still contain an edit tool call. A text-matching loop exits there, and the edit never runs. The reverse also happens: the model finishes without ever writing "done", and the loop spins on.

The reliable signal is structural, not linguistic: does the reply contain a tool call? That is what stop_reason encodes. Parsing prose is the same mistake as parsing a log message to decide control flow when a return code exists.

A turn is one model call plus the tool runs it triggers. The loop can run many turns before the final text-only one.

Other ways a run stops 2 min

Problem: what if the model never stops asking for tools, or its reply is cut off?

Then something other than the model's choice ends the run. Two kinds:

  • Reply-level stops from the API. max_tokens means the reply hit your limit, so it may be truncated mid-sentence or mid-tool-call. model_context_window_exceeded means the context filled. Treat both as truncated, not finished (handling stop reasons).
  • Run-level caps set in the harness. The Agent SDK has max_turns and max_budget_usd, both unlimited by default. A turn counts for each tool-call turn, plus one for the final text-only response (Agent SDK docs).

A capped run reports its outcome in a result subtype: success, error_max_turns, error_max_budget_usd, or error_during_execution. The result text exists only on success, so check the subtype before reading it.

A cap stops a run; it does not tell you the task succeeded. Use the result subtype for that.

Worked example and practice 2 min

Worked example

Task: "fix the failing test." Trace the loop, with max_turns set to 4.

  1. Turn 1: tool_use (run_tests). One test fails. Loop continues: a tool call is present.
  2. Turn 2: tool_use (read_file). Loop continues.
  3. Turn 3: tool_use (edit_file). Loop continues.
  4. Turn 4: tool_use (run_tests). Tests pass, but the model still needs a turn to say so.
  5. The cap is 4 and no text-only turn has happened: the run ends as error_max_turns with no result, though the work was done. Setting 5 leaves room for the final end_turn reply.
Your turn

A loop sees these stop reasons in order: tool_use, tool_use, max_tokens. First step given: the third reply is not an end_turn. Decide what the loop should do with it, and whether to run any tool call inside it.

Show a solution

The third reply was cut off at your token limit, so it is truncated, not finished. Do not return it as the answer. Do not run a tool call in it either, because that call may be incomplete. Raise max_tokens and retry, or ask the model to continue.

Summary 1 min

  • The loop exits on a reply with no tool call (end_turn); tool_use means run the tool and go again.
  • Completion is read from structure (stop_reason), never from words like "done".
  • max_tokens and context overflow mean truncated, not finished.
  • Caps (max_turns, budget) end runs early; check the result subtype before using result.
