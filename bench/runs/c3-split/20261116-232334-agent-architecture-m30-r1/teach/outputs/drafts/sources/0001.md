# Sources for lesson 0001 (O3: context and memory in an agent)

All pages opened on 2026-11-16.

## Primary

### Effective context engineering for AI agents (Anthropic Engineering, 29 Sep 2025)
- URL: https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- Who: Anthropic Applied AI team (Rajasekaran, Dixon, Ryan, Hadfield). Vendor engineering post, primary expert source on agent practice.
- Supports:
  - Context is the set of tokens given to the model when it generates; it is a finite resource with diminishing returns ("attention budget", "context rot").
  - Compaction: summarize a conversation nearing the limit and start a new window with the summary.
  - Structured note-taking: the agent writes notes to storage outside the window and reads them back later (memory across long tasks).
  - Just-in-time retrieval: keep lightweight references (paths, queries) and load data with tools at run time; hybrid with upfront loading is possible.
  - Sub-agents return a condensed summary (often 1,000-2,000 tokens) to a lead agent.
- Why primary: it covers every clause of O3 in one readable page and ties to the makerspace case (long manuals, notes between visits).

## Others

### Context windows (Claude API docs)
- URL: https://platform.claude.com/docs/en/build-with-claude/context-windows
- Supports: the context window is all text the model can reference, including its own output, a "working memory", distinct from training data; each turn re-sends prior history so tokens accumulate; system prompt, messages, tool results and tool definitions all count; accuracy and recall degrade as tokens grow (context rot); overflow returns an error ("prompt is too long") or stops generation; compaction and tool-result clearing as management. Sizes up to 1M tokens depend on the model. Product-specific; use for the mechanism, not for company comparison.

### Memory tool (Claude API docs)
- URL: https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool
- Supports: memory between sessions as files in a /memories directory that the model creates, reads, updates and deletes through tool calls; the application runs the operations, so storage is client-side and the developer controls it; the model checks memory before starting; the multisession pattern (progress log read at start, updated at end); memory preserves what must survive summarization; advice to cap file size and expire old memories.

### Memory overview (LangGraph / LangChain docs)
- URL: https://docs.langchain.com/oss/python/concepts/memory
- Who: LangChain, framework documentation.
- Supports: short-term memory is thread-scoped (message history in agent state, saved by checkpoints); long-term memory is shared across threads and stored in namespaces; semantic (facts), episodic (past experiences) and procedural (instructions) memory; writing memories on the hot path versus in the background; a full history may exceed the window, so trim or filter stale messages; long contexts also raise cost and latency.

### Introducing Contextual Retrieval (Anthropic, 19 Sep 2024)
- URL: https://www.anthropic.com/news/contextual-retrieval
- Supports: retrieval over a long document set: split into chunks, embed for semantic search, BM25 for exact terms (such as error codes), merge, put top-K chunks in the prompt; a knowledge base under about 200,000 tokens (about 500 pages) can go in the prompt with no retrieval, and prompt caching cuts cost; claimed failure rates 5.7% baseline, 3.7%, 2.9%, 1.9% with contextual embeddings, BM25 and reranking (vendor-reported). Note: the page URL is under /news/ though it was fetched as an engineering post.

### Lost in the Middle: How Language Models Use Long Contexts (Liu et al., TACL vol. 12, 2024)
- URL: https://aclanthology.org/2024.tacl-1.9/
- Who: Liu, Lin, Hewitt, Paranjape, Bevilacqua, Petroni, Liang; peer-reviewed.
- Supports: on multi-document QA and key-value retrieval, accuracy is best when the relevant text is at the start or end of the input and drops when it is in the middle, even for long-context models. Independent evidence for "more context is not better".
