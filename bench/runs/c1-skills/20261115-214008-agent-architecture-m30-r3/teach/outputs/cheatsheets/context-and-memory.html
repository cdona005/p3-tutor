Context and memory in an agent

From lesson 1.

Where information lives

PlaceWhat goes thereSurvives the session?Cost
Context (history)Instructions, tool descriptions, question, tool resultsNoPaid again at every later call
Saved notes or recordsFacts that stay true and are needed later, such as training statusYes, if the program saves and loads themSmall, loaded when needed
Retrieved documentsLong material, such as manualsStored outside; only matches enter the contextA few chunks per call

Rules

  • The model keeps nothing between calls; the program re-sends the history.
  • Input tokens over a request = sum of each call's whole context, so long loops cost more than linearly.
  • Fitting in the window is not the same as being used well: keep the smallest set of high-signal tokens.
  • Make tools return less; compact long histories; use sub-agents for messy searches.
  • Memory is not automatic: decide what to save, write it, and load it.

Sort test

For any fact ask: how long does it stay true, how big is it, does the model need it on every call?
