Context and memory in an agent

By the end of this lesson you can say what the makerspace assistant keeps in its context, what it saves between sessions, and how it finds the right page in a long manual.

Warm-up 1 min

Recall

In the agent loop, what does the program do with a tool's result before the next model call?

Check your answer

It sends the result back to the model as part of the next input. Today's question is what that input contains, and how long it can grow.

The context window 2 min

Each model call is separate, so how does the model "know" what happened three steps ago? It does not. The program sends it everything again, every time.

That text is the context: the system prompt, the tool descriptions, the conversation so far and every tool result. The context window is the most text, counted in tokens, that the model can take in for one call. As a conversation goes on, each user message and each reply are added, and earlier turns are kept in full (Claude docs, context windows).

Think of it like a function with no global state: the model sees only its arguments. The context is the argument list, and you rebuild it on every call. Where the analogy stops: the argument has a hard size limit, and you pay for every token in it, on every call.

A bigger window does not make this free. Anthropic reports that as the number of tokens grows, the model's ability to recall information from the context decreases, an effect it calls context rot, so the goal is the smallest set of high-signal tokens (Anthropic, context engineering).

Check yourself

An agent makes 10 model calls for one request. A manual page of 2,000 tokens is fetched at call 2 and never removed. Roughly how many times is that page sent to the model?

Show the answer

Eight times: the program resends everything in the context on each call after the page is added.

Between steps and between sessions 2 min

If the context is rebuilt on every call, what survives when a student closes the chat and returns tomorrow? Only what your program saved.

  • Between steps: the message list the program keeps in a variable. It is carried into every call of one conversation.
  • Between sessions: nothing, by default. The model has no memory of earlier conversations; anything that should last must be written to storage and loaded back in.

LangChain's docs name the same split: short-term memory is scoped to one thread, saved by a checkpointer, and long-term memory is stored outside any thread so it can be recalled from any later one (LangChain, short-term memory; long-term memory).

A common mix-up

"The model remembers the student from last week." It is tempting because chat apps appear to remember. In your own code, a new session starts with an empty message list. Unless your program stores the training status and loads it, the model has never heard of that student.

Check yourself

Which belongs in storage outside the context between sessions?

Show the answer

The training status: it must outlive the conversation, so it goes in a database or file.

Retrieval and notes 2 min

A laser cutter manual may run to hundreds of pages. Pasting all of it into every call wastes tokens and, per context rot, can hurt accuracy. What do you do instead?

Retrieval means fetching only the relevant pieces, on demand. In your agent that is a tool, such as search_manuals(query), that returns the few best passages. Anthropic describes this "just in time" approach: keep light references and load data into context only when needed (Anthropic, context engineering).

Notes are the reverse direction: the agent writes facts to storage outside the context and reads them back later, so it can keep going after the context is trimmed or summarized (same source). For you, a note is "student 42 trained on laser cutter, 3D printer".

Check yourself

A student asks for the laser cutter's maximum material thickness. Which design fits your small budget best?

Show the answer

The search tool: it loads one relevant passage instead of the whole manual.

Worked example and practice 2 min

Worked example

A returning student asks: "Can I use the CNC router?" Where does each piece of information come from?

  1. Program starts a new session: message list is empty, so it loads the student's saved training record (long-term memory) into the context.
  2. Model requests search_manuals("CNC router training requirement"); only the top passage returns and joins the context (retrieval).
  3. Model compares the two and answers. The answer is appended to the message list (short-term memory).
  4. Program saves any change, such as a new booking, back to storage, so the next session sees it.
Your turn

A student asks mid-chat: "Book the same machine I booked earlier in this conversation." Step 1 is given: the earlier booking is in the message list. Decide which kind of memory answers it, and whether you need retrieval or storage.

Show a solution

It is short-term memory: the booking is already in the context for this conversation, so no retrieval or storage is needed. If the student had said "the machine from last week", it would need long-term storage loaded at session start.

Summary 1 min

  • The context is everything sent on a call; it is rebuilt and billed each time, and it has a size limit.
  • Between steps, the program's message list carries state; between sessions, only saved data does.
  • Retrieval loads relevant pieces in; notes write facts out. Both keep the context small.

Say it in your own words: for the makerspace assistant, what goes in the context, what goes in storage, and what gets retrieved?
