Context and memory in an agent

By the end of this lesson you can decide, for the makerspace assistant, what goes in the context window, what is saved between sessions, and how a long manual is searched.

The program sends it back to the model as new input, and the model decides the next action. Today's question is what that growing pile of input does to the model, and to your bill.

The context window 3 min

A model has no state of its own between calls. Everything it can use for one call has to be in the text you send it. What do you send, and is there a limit?

The context window is all the text the model can see when it writes its next output: instructions, tool descriptions, the conversation so far, and tool results (Claude docs: context windows). It is measured in tokens and has a hard maximum. Think of it as the arguments to a function: the function sees only what you pass in.

In an agent loop, each step adds to that text, so every later call sends a longer input. More tokens in also means more cost per call. Fitting under the maximum is not the only concern: Anthropic's engineers describe context rot, where the model's recall of details gets worse as the window fills, and they advise using the smallest set of high-signal tokens that does the job (Effective context engineering for AI agents).

Between steps and between sessions 2 min

A student books a laser cutter on Monday and returns Thursday. What does the assistant remember?

  • Between steps: the context is kept, because your program keeps the growing list of messages and resends it. This is short-term memory.
  • Between sessions: nothing is kept by default. A new session starts with an empty window. Anything the assistant should know on Thursday must be saved by your code, in a file or database, and loaded in again.
A common mix-up

"A bigger context window means the assistant remembers students." A window is only the input to one call. It does not persist after the session ends, however large it is. Persistence is something you build.

Retrieval and notes 2 min

The machine manuals are far too long to put in every call. How does the assistant get the right page?

Retrieval keeps the manuals outside the window, split into chunks. A search tool returns only the few chunks that match the question, and only those enter the context. This is just-in-time loading: keep light references and pull in data when needed, instead of preloading everything (Anthropic). It works like an index lookup rather than loading a whole table into memory. Chunking can lose context, such as which machine a page is about; Anthropic's contextual retrieval adds a short explanation to each chunk and cut failed retrievals by up to 67% in their tests.

Notes are the other half: the agent writes facts outside the window, such as "Sam: laser cutter training passed", and reads them back in later, in this run or in a new session (Anthropic). When a long run nears its limit, compaction summarizes the history and continues with the summary.

Worked example and practice 1 min

Worked example

A student asks, "What speed should I use for acrylic on the laser cutter?" Plan the memory.

  1. Instructions and tool descriptions: in the window every call, kept short.
  2. The question: in the window.
  3. The answer lives in a manual: the model calls search_manuals, and only the top few chunks come back.
  4. Session ends: save one line to the student's notes, such as the machine they asked about.
Your turn

The same student returns and asks, "Can I book the laser cutter?" Which of the four items above change, and what must load before the model can answer?

Show a solution

The retrieval step is replaced by a calendar tool call. Before answering, your code must load the student's saved training status into the new, empty context. Otherwise the assistant cannot know whether the student is trained.

Summary 1 min

  • The context window is everything the model sees in one call; it grows each step and you pay for it each call.
  • Context is kept between steps by your program; between sessions, nothing is kept unless you save it.
  • Retrieval brings in only the relevant chunks of long documents; notes persist small facts.
