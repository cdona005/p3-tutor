Warm-up 1 min

Recall

In the agent loop, who runs a tool, the model or the program? And what does the program do with the result?

Check your answer

The program runs it, then adds the result to the model's next input and calls the model again. That input is what this lesson is about.

The context window 2 min

The model remembers nothing between calls. So what does it work from at each step? Only the text you send in that call.

That text is the context: the tokens included when the model generates a response (Anthropic Engineering). The context window is the limit on how much it can hold, counting the response itself (Claude docs).

Everything the model sees counts toward it:

  • the system prompt and your tool definitions;
  • every message so far, including tool results;
  • the response being written.

Think of it like a function's arguments: the model is a function of its input only. Unlike arguments, the window has a hard size limit, and a fuller window costs more per call.

A common mix-up

"The model remembers the conversation." It does not. Your program re-sends the whole history each turn, and each turn's input is all prior history plus the new message (Claude docs). If it is not in the input, the model cannot see it.

Step 5 of a request runs. Which text did the model have available for that call?

Show the answer

The third option: the model sees only what the program sends in that call.

Between steps, between sessions 2 min

If each call starts blank, what survives from step to step, and from visit to visit?

  • Between steps: your program keeps appending to the context. This is also why long runs get expensive: every call pays for the whole history.
  • Between sessions: nothing, unless you save it. A new session starts with an empty context.

A bigger window does not fix this. Recall also gets worse as the context grows, a gradual decline Anthropic calls context rot (Anthropic Engineering). The goal is the smallest set of useful tokens, not the most tokens.

Check yourself

A student ends a chat today and returns next week. What does the assistant know about them?

Show the answer

The first option: only what was saved and loaded back.

Retrieval and notes 3 min

A laser-cutter manual is 200 pages. Pasting it into every request is slow and costly, and it buries the one page that matters. What instead?

Retrieval means the agent keeps light references, such as file paths, queries or page ids, and loads the data into context only when needed, using tools (Anthropic Engineering). For you: a search_manuals(query) tool returns the two best passages, not the manual.

Notes are the other half: the agent writes facts to storage outside the context and reads them back later (Anthropic Engineering). Anthropic's memory tool works this way: Claude asks to create, read or delete files, and your application runs those operations and stores the files (Claude docs). It is the same loop as before, with memory as a tool.

The third row is compaction: summarizing a conversation near the limit and starting a new context with the summary (Anthropic Engineering).

A common mix-up

"Memory is built in, so the assistant will remember students automatically." Not unless you build it. The memory tool lives entirely in your application; you decide what is stored and where (Claude docs).

Worked example and practice 1 min

Worked example

A student asks: "Can I cut 6 mm acrylic on the laser?" Decide what is loaded.

  1. Always in context: system prompt and tool definitions (the assistant needs them every call).
  2. Retrieved now: the laser manual's materials page, via search_manuals, because the answer is in a long document.
  3. Loaded from notes: this student's training record, because it is about them.
  4. Not loaded: the other manuals and last month's chats.
Your turn

A student asks, "Can I book the vinyl cutter Friday?" Step 1 is given: tools and system prompt are always in context. Decide steps 2 to 4: what is retrieved, what comes from notes, and what is left out.

Show a solution

2. The calendar result comes from a tool call, and any page on booking rules is retrieved. 3. The student's training status for the vinyl cutter comes from notes. 4. Other machines' manuals are left out.

Summary 1 min

  • The context is everything the model is given in one call; the window limits it, and fuller means costlier and less reliable.
  • Context lasts across steps in a session; across sessions only saved data does.
  • Retrieval pulls the right page in; notes carry student facts between visits.
